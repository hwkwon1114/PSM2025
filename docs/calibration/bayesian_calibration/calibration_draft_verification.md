## Findings and corrections

1. **Experimental allocation:** Run 6 calibration / Runs 9 and 10 validation is researcher-directed. Four identical parameter values are present in all three saved sequences. This verifies no parameter refit, not independent held-out model development. Laboratory dimensions, fixture identities and exclusion rationale cannot be established from simulation inputs.
2. **Parameter definitions/bounds:** top/bottom magnitudes and orthotropy mapping `g*(1±o)` are implemented in `src/libshell/ZigZagSequenceGrowth.hpp:624–627` and the sequence accumulation path in `src/simulations/Sim_Bilayer_Growth.cpp:2624–2630`. Bounds and estimates agree with recovery frozen config and summary. These are effective engineering-strain inputs, not independently measured material constants.
3. **Mesh/settings:** all three saved reference meshes have 15,251 vertices, 30,000 faces and spans 0.2 × 0.3 m. State thickness is 0.00077 m, nu=0.33, numerical E=1. Geometry code uses edgeLength=2*Lx*res, so res=.01 is dimensionless and gives 2 mm spacing. All sequences use uniform 2 mm width, disabled boundary conditions; manifests show native_hybrid, final_only, one equilibrium solve. These are model settings, not laboratory measurements or mesh convergence evidence. Layer split/normalization exposition remains an editorial check; no unsupported physical E units added.
4. **Solver:** `src/libshell/ReferenceHybrid/Core.hpp:393–449` directly calls HLBFGS update kernels and MCSRCH. Native hybrid selects sparse Newton/local-dihedral Hessian assembly; `ReferenceHybrid/Hessian.hpp` uses TinyAD scalar types. `ReferenceHybrid/ShellProblem.hpp` evaluates ordinary energy/gradient through `energy.compute`, so TinyAD is attributed specifically to Hessian assembly. Acceptance in `NativeHybridShellSolver.hpp:398–406` checks raw gradient norm <= tolerance plus finite values, termination status and positive pivots. Regularization is conditional, not asserted to occur on every step.
5. **Alignment/objective:** `calibration/ewcal/material_frame.py` fits proper rotation to corresponding reference vertices, subtracts reference-area-weighted model centroid and arithmetic scan centroid. No pose optimization against the scan. `geometry.py:127–152` confirms forward triangle distance RMS; reverse nearest-scan-point RMS weighted by reference dual areas; half-sum of squared directed RMS values. Forward P95 is an unweighted empirical quantile. Draft equations match this; no multi-case objective is claimed.
6. **Scan:** `calibration/data/processed/run6_edge_aligned_refined.json` records 14,504 accepted points and top-scan-as-midsurface approximation, now disclosed in draft. SHA256 of its NPZ matches recorded `775cce8ee6ec1552d53067786de41334af4869d2c298712a211024448b47bf47`. Fixed settings recorded there match the frozen config. Full raw-STL reprocessing was not repeated. Wording narrowed to fixed preprocessing within the reported search stage, rather than an unsupported claim covering all historical development.
7. **Bayesian optimization:** GP fit uses negative natural log objective, Matérn 5/2 ARD; parameter map logs the first two coordinates. Final recovery checkpoint records `proposal_method=success_aware_separation`, q=4, nine waves, status budget_complete, and wave diagnostics with minimum separation .08 and 1024 posterior samples. `success_aware_bo/model.py` separately models completion and evaluates success-aware improvement in log form; `separation.py` jointly proposes four points. Draft corrected to describe this verified final stage, not ordinary EI throughout. An unqualified initial-space-filling claim is not supported by the inspected archive. Earlier stage-policy provenance is still incomplete.
8. **Ledger:** recovery evaluations.jsonl has unique IDs 1–240. IDs 1–80 are prior training-only records, 70 valid/10 timeout; IDs 81–240 are 151 valid/9 timeout. Overall minimum valid objective is attempt 209, 1.182313603689339 mm. Last-80 counts (74 valid/6 timeout) and last-36 counts (33 valid/3 timeout) agree with summary. These are stored records, not proof of total original solver calls, retries or completion chronology. No convergence/global-optimum claim.
9. **Results:** rechecked summary values and recomputed sqrt((forward_RMS²+reverse_RMS²)/2) for all cases. Run6: 1.1823136037, .6497201257, 1.5406474850, forward P95 1.2263830306 mm. Run9: 1.2472505298, .8904194490, 1.5226361920, 1.6992643256 mm. Run10: 1.2480932979, .7623938532, 1.5919263090, 1.5662563744 mm. Draft rounding is correct. Full geometric distances were not recomputed from meshes in this audit.
10. **Interpretation:** bottom orthotropy .960306 is near +1; bottom growth lies low in its log interval. This motivates, but does not replace, sensitivity/reduced-model checks. Changed assertion that sampling explains reverse error to a sensitivity statement: contribution not isolated. Changed 'not independent experimental replicates' to 'not uncertainty estimates from repeated experiments': independence cannot be inferred or denied from these summaries.
11. **Figures:** existing checked figure code implements fixed-y interpolation, shared limits, disclosed missing support, no smoothing fit, and labels model output Analytical. Height residual is not geometric objective. Three separate manuscript figures exist; proposed combined Figure 5 remains explicitly unassembled. The old Run6 overlay is 12x exaggerated and is distinct from the three-case section figure.
12. **References:** software attribution is HLBFGS (Yang Liu, 2010), not CVT as a generic optimizer reference. TinyAD bundled README supplies authors, title, Computer Graphics Forum 41(5), 2022; draft metadata completed accordingly. A BO reference is still to be selected; no citation number inherited from TinyAD.
